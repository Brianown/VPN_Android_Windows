# 加密、隐私与被监听的边界

> 这一页回答两个问题：
> 1. LiteTunnel / WireGuard 到底加密了什么？
> 2. “加密再加密”能不能做到任何人（包括运营商、VPN 服务器、黑客、任何部门）都看不到我访问什么？

## 1. WireGuard 已经加密了什么

WireGuard 使用现代密码学：

- **Curve25519** 做密钥交换；
- **ChaCha20-Poly1305** 做数据加密和完整性校验；
- **BLAKE2s** 做哈希；
- 每个客户端还配置了 **PresharedKey（预共享密钥）**，它会和公钥协商结果混合，相当于在公钥加密之上再加一层对称密钥。

所以，客户端到服务器之间的**整个 IP 包**都是加密的，包括：

- 你访问的网站域名 / 目的 IP；
- DNS 查询（配置里 `DNS = ...` 时，DNS 走隧道）；
- HTTP 内容（如果网站是 HTTP）；
- HTTPS 的 TLS 握手、SNI、网页内容（在隧道内再套一层 TLS）。

## 2. 谁能看到什么

| 观察者 | 能看到 | 看不到 |
| --- | --- | --- |
| 本地 Wi-Fi / 运营商 / 路径监听者 | 你连接了哪个 VPN 服务器、UDP 端口、包大小、时间、流量 | 你访问的网站、DNS、网页内容 |
| VPN 服务器 | 解密后的目的 IP、DNS（如果明文）、HTTP 内容；HTTPS 的 SNI（除非 ECH） | HTTPS 网页正文（由网站证书保护） |
| 目标网站 | VPN 服务器 IP、浏览器指纹、登录信息（你主动提交的） | 你的家庭/手机公网 IP |
| 云厂商 | 连接时间、流量大小等元数据，可能保留日志 | 隧道内的内容 |
| 黑客 | 如果服务器/客户端被入侵，可能拿到私钥 | 正常情况下的隧道内容 |

因此：

- **内容**：WireGuard + HTTPS 已经能防止路径上的窃听；
- **访问记录**：本地网络看不到，但 **VPN 服务器看得到目的地**；
- **身份**：目标网站看到的是服务器 IP，但服务器知道你真实的连接 IP（除非再做匿名网络）。

## 3. “再加密”能解决什么，不能解决什么

### 3.1 同一个服务器再套一层加密：没有意义

如果客户端只是把同一个包再加密一次，然后还是发给同一个 VPN 服务器，服务器仍然要解密后转发，
它依然能看到目的地。对路径监听者来说，第一层 WireGuard 已经足够；第二层不会让它更安全。

### 3.2 真正有意义的三类增强

**A. 抗封锁（不让网络识别出这是 VPN）**

WireGuard 是 UDP，特征明显。换 TCP + TLS 伪装更有效，例如 Xray 的 VLESS + REALITY。
这类方案使用开源客户端 v2rayNG / v2rayN 直接导入链接，但**本项目自带客户端只支持 WireGuard**。
详见 [china.md](china.md)。

**B. 隐藏“客户端是谁”（让出口看不到你的真实 IP）**

多跳网络：客户端 → 入口节点 → 出口节点 → 网站。出口只看到入口的 IP，而不是你的 IP。
但如果入口节点会解密并转发，它仍然知道“你访问了什么”。要连入口也不知道目的地，
需要像 Tor 一样的洋葱路由，由中间节点逐层转发。

**C. 隐藏“访问了什么”（让服务器也不知道目的地）**

使用 Tor 或可信的多跳匿名网络。此时 VPN 只负责把流量送进 Tor，Tor 出口才知道最终网站；
但 Tor 出口仍然能看到未加密的 HTTP 内容，而且速度会明显下降。

### 3.3 结论

- “加密再加密”可以让**同一段链路上的监听者**多一层障碍，但不能让**出口服务器**失明；
- “任何部门、任何黑客都绝对无法监听”在技术上无法保证：端点被入侵、流量关联分析、法律调查、
  恶意软件、浏览器指纹都可能暴露信息；
- 如果你看到某个软件这样宣传，应该保持怀疑。

## 4. 按你的威胁模型选择

| 你的目标 | 建议 |
| --- | --- |
| 防止公共 Wi-Fi / 运营商偷看内容 | 当前 WireGuard 方案已足够；配合 HTTPS |
| 防止本地网络知道你访问哪些网站 | WireGuard 已隐藏目的；确保 DNS 在隧道内 |
| 不想让 VPN 服务器知道目的地 | 使用 Tor 或多跳匿名网络，或把出口放在你信任的司法辖区 |
| 在中国大陆稳定访问境外网站 | 优先 TCP/TLS 伪装（Xray REALITY），见 [china.md](china.md) |
| 防止服务器被入侵导致私钥泄露 | 及时更新系统、限制 SSH、关闭不必要的服务、定期轮换密钥 |

## 5. 日常加固清单

1. **全站 HTTPS**：浏览器安装 HTTPS-only 插件，不要登录 HTTP 网站；
2. **加密 DNS**：客户端使用 DoH/DoT，或让 VPN 服务器使用可信的加密 DNS；
3. **防止 IPv6 泄漏**：本项目客户端只接管 IPv4，若本地有 IPv6，建议在系统/路由器上关闭 IPv6；
4. **不要复用密码**，开启网站两步验证；
5. **服务器最小化暴露**：只开 SSH 和 UDP VPN 端口，SSH 用密钥登录，禁用密码登录；
6. **定期更新**：`apt-get update && apt-get upgrade`，关注 WireGuard / Xray 安全公告；
7. **不要公开分享** `.conf`、二维码、私钥截图；
8. **设备丢失**：立即在服务器上 `sudo litetunnel del 设备名` 吊销对应客户端。

## 6. 合规与责任

加密和 VPN 本身是合法的网络技术，但不同国家和地区对跨境网络访问、匿名工具和加密通信有不同规定。
请仅将本项目用于合法的学习、远程办公、访问自有服务器等用途，遵守当地法律和云服务商条款。

**任何软件都不能承诺“绝对不被任何部门监听”。** 如果有人这样承诺，那是在利用你对安全的不了解。
